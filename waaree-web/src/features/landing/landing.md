# Landing feature (public showpiece)

**Folder:** `src/features/landing/`
**Backend module:** none
**Routes using it:** `/` (`src/app/(site)/page.tsx`) and `/factories/[slug]`

## Purpose
A full replacement for waaree.com’s homepage. It is light mode, emotional and scroll-driven, and covers every section of the current homepage. Built to make Waaree want their whole website rebuilt this way. Inspired by Stripe, Apple, Clay and Arquitel, with original design.

## Story
The page is **“The Story of Waaree”**, a presentation, not a copy of waaree.com’s homepage: five acts (`chapters.ts`: who we are → our journey → progress → where it’s going → why it matters). `StoryNav` replaces the site mega-menu here (act progress bar, current chapter, chapter menu, Films, Get in touch); other pages keep `LandingNav`. Headings state the point with its number. New: **Waaree now** (`WaareeNow`: billboard of the biggest builds, the build board grouping every site by stage with `BuildGlyph`, Netflix-style rows, data `data/projects.ts` from IAR26), **What’s next** (`WhatsNext`: dated targets FY27 → 2040, market to scale, FY27 strip), docked strips (`Row` + `ProjectCard` in `ProgressRow.tsx`), **Films** (`data/films.ts`, 14 verified official YouTube films, one `FilmPlayer` for the page). Removed the per-site build status picker and the duplicate “Beyond India” cards from Factories.

## Rules & gotchas
- **Hand-offs (globe → Inside the panel → Factories).** One frame joins them: a module seen straight from above, centred, `bridgeWidth(W, H)` wide (`three/bridge.ts`; DOM: `BRIDGE_BOX`). Each scene sizes its camera to it; `/waaree/story/panel-top.jpg` is a render of PanelScene at progress 0 cropped to it (re-render it if the module’s look changes). The next chapter overlaps the last screen of the previous one (`components/handoff.ts`: `-mt-[100svh]`, stage transparent until it pins), so the swap is an invisible cut with no scroll between. Anything that must be exact at a cut runs on a `scrub: true` trigger (no lag): the hero’s growing panel, `anatomy.out`. Straight-down cameras blend `camera.up` to −z, or tiny drifts roll the view.
- **Performance (read before adding a 3D scene).** Every scene goes through `three/useStage.tsx`: wrap it with `const { wrap, mounted, frameloop, onWarm, dpr } = useStage()`, render `{mounted && <Canvas frameloop={frameloop} dpr={dpr(x)} …>…<WarmUp onReady={onWarm} /></Canvas>}`. Scenes are set up one at a time, in page order, starting ~0.5 s after load, and then kept alive (≈10 WebGL contexts); nothing renders until `compileAsync` has finished (hidden parts included); off-screen scenes idle; scenes more than ~1 screen away drop to 0.15 dpr to free GPU memory (no context loss); `gl.debug.checkShaderErrors` is off (it forces blocking compiles). Per-frame DOM writes go through `setStyle` (writes only on change). Shader compiles are the cost: prefer `meshStandardMaterial`; keep physical/transmission, bloom and shadow maps to scenes that need them (only Inside the panel has bloom + transmission). Every Canvas gets `resize={NO_SCROLL_MEASURE}`: R3F’s default measures on scroll with a debounce that never settles during a continuous scroll, which delayed scene setup by seconds and pushed it mid-chapter. Judge smoothness on a **production build** (`pnpm build && pnpm start`): dev mode is several times slower and double-mounts scenes.
- **FY26 annual report is a source** (2026-11-02, approved): figures in `data/annual-report.ts`.
- **Inside the panel:** no tone mapping (white must stay white); Bloom threshold 1.15 so only the carriers, oxide and glints glow. The studio is a procedural `Environment` with a grey backdrop: a black env turns metal black, a too-bright one washes the cells out. DOM labels are pinned to `object3D` anchors each frame; layers are found by `name` (React Compiler lint forbids ref callbacks that write a ref object).
- **Real data only.** Facts and figures from waaree.com or cited press (see `docs/research/waaree.md`); photos only from Waaree’s own media; no decorative “example” data. Globe hardware sits only at real Waaree sites and projects.
- **White base, like Waaree’s own site.** No dark sections. Colour lives inside scenes (hero sky, 3D stages) and always fades to white.
- **Page grammar:** every chapter uses `ChapterHeader` (number, eyebrow, headline left, intro right on one baseline) and white cards with hairline borders. No dark imagery behind text.
- **Say it once.** Each fact lives in one place: the headline numbers (25.8 GW, 5.4 GW, 24+, 40 quarters) only in Who we are; site facts only on the map and site pages; news only in the Newsroom. Headlines must not echo each other.
- **One visual language per section** (don’t reuse a style elsewhere): 3D Earth (hero) · studio module + cell (Inside) · particle morph (How it’s made) · aerial + gauges (Who we are) · capacity ribbon (Our story) · hologram (Factories) · glass skyline (Why) · rupee sun (Growth) · living island (Impact) · product photos (Portfolio) · Waaree photography (Solutions) · film (Excellence).
- **Data honesty:** reported figures carry their source; estimates show their working on the page; interpolated lines are never quoted as numbers.
- **Sideways rows**, if one is ever needed: no visible scrollbar, snap, edge fades, arrows in the margin on hover (Netflix-style).
- **Backgrounds:** chapters alternate white / mint (`tone="mist"`): a real band per chapter whose top and bottom melt into white, so sections are distinct without hard lines. Spacing follows the common standard: 192 px between chapters on desktop (md:pt-28 + md:pb-20), 144 px on phones (pt-[5.5rem] + pb-14), the same everywhere; headings land ~110 px below the top, clear of the floating nav. No per-section overrides.
- **People:** every scene with people shows women and men (`female` on `Figure` / `Person`: long hair or a ponytail under a hard hat, an optional kurta/dress).
- **Photos vs 3D:** Waaree’s own photography carries Who we are, Solutions and Impact (values); everything else is real-time 3D. No figure illustrations.
- **Hero text** stays dark on the light sky (no scrims or panels: they dulled the page). On squarer screens the Earth settles smaller and further right (`mid` in Globe), so text is never covered.
- **Sun motes:** `SunMotes` drifts warm light particles up through the whole hero (CSS only, deterministic positions, still under reduced motion).
- **Globe arrays:** Waaree sites + the Vietnam EPC project are sourced; the other arrays represent “modules supplied to 24+ countries” (exact list not published; replace with Waaree’s list when shared).
- **Arcs abroad:** drei `<Line>` 2 px with a green (#19d27a) → sky-blue (#2ab4f2) gradient, bright pulses.
- **India on the globe:** a soothing green border (#7fe0ab): drei `<Line>` 1.6 px inside a 7 px line at ~16% opacity, from the official outline (specks under 24 points skipped). No per-vertex glow sprites (they pile up into blobs). A faint tint inside.
- **Moods:** `Scene mood` = dawn · morning · golden · dusk · overcast · clean; gradient ids are per-scene (`useId`) so moods never leak between cards. Off-screen scenes pause (`data-live`).
- **Illustrations:** build from the kit only, so every scene shares one look. Round any trig output (`r3`): server and browser differ in the last digit, which breaks hydration.
- **Every chapter fits one screen when you jump to it:** sections land at the very top (Lenis `anchors.offset: 0`) with top padding that clears the floating nav, and the key visual is sized in `svh` (Factories map, film, form). Factories uses a side-by-side first screen (`ChapterHeader` in the left column).
- **Headings:** `[data-split]` h2s (and the hero h1) reveal line by line with GSAP SplitText. Split after `document.fonts.ready` inside `contextSafe`, use `fromTo` (React dev double-runs break `from`), and give masks room for descenders (`roomForDescenders`).
- **Performance:** the canvas stops rendering off-screen (IntersectionObserver → `frameloop`) and drops to 1× DPR when drei `PerformanceMonitor` sees it struggle. A soft glow stands in while the Earth loads.
- **Round globe:** the Earth stays on the camera axis and the frame moves (`camera.setViewOffset`). Moving a sphere sideways in a perspective view stretches it on wide screens.
- **React Compiler lint:** don’t mutate `useMemo` values in `useFrame`. Mutate through a ref (`ref.current.material.uniforms…`) or module-level scratch objects, and write `useMemo(() => make(), [])`, never `useMemo(make, [])`.
- **No drei `<Html>`.** It created extra React roots, so overlays are plain DOM.
- **Textures:** `public/earth/` (about 1 MB of WebP, public domain; see its README).
- **Reduced motion:** Lenis is off, the scroll timeline follows directly, and the idle spin stops.
- Tests: `tests/e2e/landing.spec.ts`. Screenshots go to `E2E_SCREENSHOTS`.
- The dev server sometimes misses new Tailwind classes in this OneDrive folder. Restart it, or save `next.config.ts`.
